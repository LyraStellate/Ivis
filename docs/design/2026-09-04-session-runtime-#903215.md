## 背景と課題

[全体設計 #312078](2026-09-04-agent-expansion-overview-%23312078.md) の一部。セッションが自分の場所と区切りを持たない。

- 作業ディレクトリは全セッション共通 (`internal/config/config.go` の `WorkspaceDir`)。`internal/engine/exec.go` がそれをそのまま `ExecContext.Workspace` へ渡すため、どの会話から書いても同じ場所に落ちる。別々の依頼の成果物が混ざり、どれが消してよいファイルか判別できない。
- 会話は前へ進むだけ。誤った前提のまま進んだ会話をやり直すには、セッションごと作り直して最初から打ち直すしかない。
- どれだけ文脈を使ったかが見えない。ローカルモデルの文脈は狭く、溢れれば古い発言から落ちるが、利用者にはその瞬間が分からない。応答が急に噛み合わなくなった理由が読めない。

## ゴール / 非ゴール

### ゴール

- セッションごとに作業ディレクトリが分かれる。
- 任意の利用者発言まで会話を巻き戻せる。
- 直前のターンで文脈をどれだけ使ったかが入力欄から見える。

### 非ゴール

- **並列エージェントセッション。** 今回入れるのは区切りだけ。
- **文脈が溢れる前の自動要約・切り詰め。**
- **ワークスペースの巻き戻し。** ファイルは戻さない。
- **セッション削除時の作業ディレクトリの削除。** 利用者が置いた材料や成果物を消さない。
- **既存の作業ディレクトリの中身の自動移動。**

## 設計案

### 採用案

**ワークスペース** — 設定の作業ディレクトリを親とし、その下に実行形態を表す 1 段と、セッション ID の 1 段を置く。直列に 1 本ずつ進むセッションは `<作業ディレクトリ>/series/<セッション ID>/` を使う。

実行形態の段を挟むのは、この先の並列セッションが別の形の識別子 (1 つのセッションから枝分かれした複数の実行) を持つためである。そのときに直列側のパスを変えずに済む。

境界の判定 (`internal/tools/path.go`) はこの根を差し替えるだけで効く。判定の仕組みそのものは変えない。

**巻き戻し** — 起点に選べるのは利用者の発言だけとする。確定すると、その発言と、それ以降の全ての発言 (委譲された子の発言を含む) を消し、その本文を入力欄へ戻す。

利用者の発言に限るのは、会話をやり直す単位が「あの依頼から」だからである。モデルの発言の途中を起点にできても、消したあとに何を送ればよいかが決まらない。本文を入力欄へ戻すのは、巻き戻す動機がほぼ常に言い直すことにあるためで、消してから同じ文を打ち直させる理由がない。

**文脈使用量** — 生成のたびに、モデルへ送った入力のトークン数と、そのモデルの文脈長を記録する。入力欄に円形のグラフで使用率を出す。

トークン数を自前で数えず提供元の実測値を使うのは、数え方がモデルごとに違うためである。推定は必ずずれ、残量が少ない領域ほどずれが効く。

### 検討した代替案

- **セッションごとではなくエージェントごとにワークスペースを分ける。** 同じ相手に続けて頼む作業がまとまるが、1 つの会話の中で複数のエージェントが働くため、1 つの依頼の成果物が複数の場所へ散る。探す単位が会話である以上、区切りも会話単位が合う。
- **設定の作業ディレクトリ直下にセッション ID を並べる。** 1 段浅くなるが、並列セッションを入れるときに直下へ別種の識別子が混ざり、どちらの規則の名前か見分けられなくなる。
- **巻き戻しを非破壊にする (消さずに枝として残す)。** やり直しの経緯が残るが、履歴が枝を持つと、一覧・表示・モデルへ渡す履歴の全てが「どの枝か」を扱うことになる。要求は削除であり、枝を見せる画面も今は無い。
- **文脈量をトークン数の推定で出す。** 提供元への問い合わせが要らなくなるが、ずれるため見えることの意味が薄れる。
- **溢れそうなら自動で古い発言を落とす。** 会話が黙って欠けるほうが、溢れること自体より分かりにくい。今回は見せるところまでとする。

## 詳細設計

### データモデル

セッションに、直前のターンの文脈使用量を持たせる。入力トークン数と、そのときの文脈長の 2 つ。会話を開き直したときに、生成を待たずに前回の状態を出せるようにするため。発言ごとに持たないのは、見せたいのが「いま次を送れるか」であって推移ではないからである。

作業ディレクトリの場所はセッションに保存しない。セッション ID から一意に決まる派生物であり、保存すると設定の作業ディレクトリを変えたときに食い違う。

巻き戻しのためのデータは増やさない。既にある発言の順序と、委譲の親子関係だけで消す範囲は決まる。

### インターフェース

- **巻き戻し** — セッションと起点の発言を受け取る。起点が利用者の発言でなければ断る。そのセッションで生成中なら断る。成功したら、消した件数と入力欄へ戻す本文を返す。
- **文脈使用量** — セッションの取得に含めて返す。専用の経路は設けない。生成中は既存のイベントの流れで更新する。

生成の終了イベントに、そのターンの入力トークン数と文脈長を載せる。画面はこれを受けてグラフを更新する。

送信した本文が保存されたことも、識別子とともにイベントで返す。画面は送った本文を自前で先に置くため、保存された識別子を受け取らないと、その発言を指す操作 — つまり巻き戻し — が会話を開き直すまで使えない。

文脈長は、こちらが提供元へ渡す値そのものを分母にする。エージェントの生成パラメータに指定があればそれを、無ければ設定の値を使い、モデル自身が持てる値が分かるならそこで頭を打つ。モデルが持てる最大値を分母にしてはならない。渡した値より大きい分母で割ると、まだ余裕があるように見えているうちに溢れる。

渡す文脈長を明示するのは、省くと提供元の既定 (Ollama は 4096) で走るためである。ツールの結果を何度も往復する使い方ではそれはすぐ埋まり、埋まると古い側から黙って捨てられる。捨てられる先頭には指示文があるので、エージェントは自分が誰で何を任されていたかを失い、応答は途中で終わる。設定に既定の文脈長を置き、利用者が上げ下げできるようにする。

### 処理フロー

**セッションの作成** — 会話を作った時点で作業ディレクトリも作る。利用者が材料を先に置けるようにするため。場所は画面から確認でき、開けるようにする。

**ツールの実行** — 実行の文脈に渡す境界を、設定の作業ディレクトリではなくそのセッションのディレクトリにする。委譲された子も同じ場所を使う。子は親の依頼の一部を担うのであり、成果物の置き場を分ける理由がない。

**巻き戻し** — 起点の発言以降を、委譲の子も含めて消す。子は親の発言にぶら下がるだけでデータベース側の連鎖削除は効かないため、明示的に消す。消したあとセッションの更新時刻を直し、文脈使用量は不明に戻す。次の生成まで実測値が無いため。作業ディレクトリには触らない。

**文脈使用量の更新** — 生成の最終応答に含まれる入力トークン数を読み、セッションへ保存し、イベントとして流す。委譲された子の生成では更新しない。見せているのは利用者が次に送れる量であり、子は別の文脈で走るためである。

### 画面

入力欄の中に円形のグラフを 1 つ置く。中心に使用率、周囲の弧が量を表す。分母が分からないときは出さない。余裕がある間は目立たない色で、残りが少なくなったら注意を促す色へ変える。触れると入力トークン数と文脈長を数値で示す。

巻き戻しは、利用者の発言の行から呼ぶ。確定には既にある確認の窓 (`web/src/lib/Confirm.svelte`) を使い、「ここから後の N 件を消す」と件数を示す。ファイルは戻らないことも添える。

セッションの作業ディレクトリの場所は、会話の情報として出す。

## テスト方針

- **境界の判定**を、セッションごとのディレクトリに対して検証する。別セッションのディレクトリへ相対指定で到達できないことを含める。既存のパス検査に、根を差し替えた場合を足す。
- **巻き戻し**が、起点以降の発言と委譲の子だけを消し、それより前を残すことを検証する。起点より前に委譲があった場合に、それが残ることも含める。
- **巻き戻しの拒否**として、モデルの発言を起点にした場合と、他のセッションの発言を起点にした場合を検証する。
- **文脈使用量**が、実測値を得られたときに保存され、分母が無いときに出ないことを検証する。あわせて、分母が実際に提供元へ渡した値と一致すること、モデルの持てる値で頭打ちになることを検証する。
- **生成が上限で打ち切られたとき**に、その旨が利用者へ伝わり履歴にも残ることを検証する。言い終えたときには付かないことも同時に確かめる。付いてしまうと、正常な応答が毎回失敗として見える。
- **手動確認** — 実際のモデルで文脈を埋めていったときのグラフの動き、巻き戻し後に同じ依頼を送り直したときの見え方、セッションを 2 つ開いて別々のファイルを書いたときの分離。

## リスクと未決事項

- **既存セッションの見え方が変わる。** 今まで共通のディレクトリにあったファイルはそのまま残るが、どのセッションからも見えなくなる。自動で移すと、どのセッションの成果物か決められない。移さない代わりに、起動時に伝えるかどうかは決めていない。
- **作業ディレクトリが溜まる。** セッションを消してもディレクトリは残る。消す導線を設けるかは、実際に溜まってから決める。先に作ると、要らなかった場合に消す機能だけが残る。
- **文脈長が得られないモデルがある。** その場合グラフは出ない。出ないこと自体をどう伝えるかは決めていない。
- **文脈長を上げるほど記憶を食う。** 渡す量に比例して機械側の消費が増える。既定はほどほどの値に置くが、機械に合う値は使う人にしか決められない。
- **巻き戻しとファイルの不一致。** 会話は戻るがファイルは戻らないため、モデルが「まだ作っていない」と思っているファイルが既に存在する状態で再開する。避けられないので、巻き戻しの確認時に明示する。
