## 背景と課題

v1 (#694381) でエージェント・スキル・委譲の骨格ができ、実際に使い始めた段階で 2 種類の不足が出た。

**1. エージェントを増やす手段が無い。** 定義は JSON の手書きのみで、出発点は初回に書き出す雛形 2 つしかない。委譲先は各定義の `delegates` に相手の ID を列挙する形なので、エージェントを 1 体足すたびに、その相手を呼びうる全ての定義を開いて書き足すことになる。増やすほど記述が増える構造になっている。

**2. セッションが場所と区切りを持たない。** 作業ディレクトリは全セッション共通で (`internal/config/config.go` の `WorkspaceDir`)、別々の依頼の成果物が同じ場所に混ざる。会話は前へ進むだけで、誤った前提で進んだところまで戻す手段がない。コンテキストをどれだけ使ったかも見えず、溢れる瞬間が利用者に分からない。

さらに、この先「並列エージェントセッション」を作る予定がある。並列化は、セッションが自分の作業場所を持っていることを前提にする。今のうちに区切っておかないと、後から全てのファイル操作の経路を変えることになる。

## ゴール / 非ゴール

### ゴール

- 画面からエージェントを作成・編集・削除でき、その結果が定義ファイルに残る。
- 委譲の可否が、個々の定義の列挙ではなく階層 (Tier) で決まる。
- セッションが自分の作業ディレクトリを持つ。
- 会話を任意の地点まで巻き戻せる。
- コンテキストの残量が入力欄から見える。

### 非ゴール

- **並列エージェントセッションそのもの。** 今回入れるのはその前提となる区切りだけで、並列実行は作らない。
- **Ollama 以外のプロバイダ対応。** #694381 から継続。
- **エージェント定義の配布・取り込み。** ローカルのディレクトリを読み書きするだけ。
- **コンテキストが溢れる前の自動要約・切り詰め。** 測って見せるところまで。
- **ワークスペースの巻き戻し。** 履歴は戻せるが、ファイルは戻さない。

## リスクと未決事項

- **v1 の原則を 1 つ崩す。** 「エージェント定義は Ivis から書き戻さない」を解禁する。手で書いたコメントや整形は保存時に失われる。判断の詳細は #528664 に置く。
- **既存の定義との互換。** `delegates` を持つ定義は既に手元にある。読み込みを壊さない形で無視する。
- **既存セッションの扱い。** ワークスペースを分けると、既存セッションが今まで読んでいたファイルはその場所に無くなる。消しはしないが見え方は変わる。
- **並列化の前提が正しいか未検証。** セッションごとにディレクトリを分ける形がそのまま並列実行に使えるかは、実際に並列を作るまで確かめられない。ここが外れると区切り方をやり直すことになる。
