# Ivis

Ollama に接続して使う、軽量な AI チャット / エージェントフレームワーク。

単一バイナリを起動してブラウザで開く。エージェントは JSON、スキルは Claude 形式の
`SKILL.md` で管理し、既存の Claude スキル置き場をそのまま探索パスに指定できる。

設計の経緯と決定は [docs/design/](docs/design/) にある。

## ビルド

フロントエンドをビルドしてから Go をビルドする。成果物はバイナリへ埋め込まれる。

```
cd web && npm install && npm run build && cd ..
go build ./cmd/ivis
```

`-o` は付けない。付けると Windows で拡張子の無いファイルができる。

**起動したままだとバイナリを上書きできない。** 実行中の Ivis を止めてからビルドする。
止めずに走らせると `The process cannot access the file` で失敗し、古いバイナリが
そのまま残る。作り直したのに画面が変わらないときは、まずこれを疑う。

## 起動

```
./ivis
```

既定で `http://127.0.0.1:8317` を待ち受ける。初回起動時に `~/.ivis/config.json` と
エージェントの雛形を書き出す。設定とエージェント定義は画面から編集でき、その結果は
そのままファイルへ書き戻る。手で書いたコメントや並び順は保存時に失われる。
スキルは読むだけで、Ivis 側から書き換えることはない。

エージェントは Tier で階層を持つ。数字が小さいほど上位で、委譲できるのは自分より
数字の大きい相手だけである。会話の入口となる `general` は Tier 0 で固定され、削除
できない。消されていれば起動時に作り直す。

会話はそれぞれ自分の作業ディレクトリを持ち、`<作業ディレクトリ>/series/<会話 ID>/`
に置かれる。ファイル操作はその中に限られる。会話を削除してもディレクトリは残る。

会話は任意の依頼まで巻き戻せる。巻き戻すとそれ以降の履歴は消えるが、作られた
ファイルは戻らない。

別マシンの Ollama を使う場合は設定画面か `~/.ivis/config.json` の
`ollama_base_url` を変える。

## 他の端末から開く

待ち受けアドレスは設定画面か `listen` で変える。変更は再起動後に効く。

- `127.0.0.1:8317` — この端末だけ (既定)
- `100.x.y.z:8317` — Tailscale などの VPN のアドレスだけに絞る
- `0.0.0.0:8317` — すべての経路に開く

Ivis に認証は無く、届いた相手はファイルの読み書きとスクリプトの実行を頼める。
ループバック以外へ束ねるなら、到達できる範囲そのものを絞ること。起動時に、実際に
開ける URL と、tailnet のアドレスがあればその印が出る。

## 開発

フロントエンドを触る間は Vite の dev server を使う。`/api` は Go 側へ中継される。

```
./ivis            # 別の端末で
cd web && npm run dev
```

テストは `go test ./...` と、フロントエンド側の `cd web && npm test`。

## 現状

v1 の基盤まで。Ollama 以外のプロバイダ、任意のシェル実行、認証、MCP 連携は
意図的に範囲外にしてある。理由は設計書の非ゴールを参照。
