# Ivis

Ollama に接続して使う、軽量な AI チャット / エージェントフレームワークです。

既存のAIエージェントフレームワークは、ローカルの小型モデルでは推論精度やパフォーマンスの面で課題がありました。Ivisプロジェクトでは、小型モデルでも高いツール呼び出し精度と軽量な動作を実現できるAIエージェントフレームワークの開発を目指しています。


単一バイナリを起動してブラウザで開きます。エージェントは JSON、スキルは Claude 形式の
`SKILL.md` で管理し、既存の Claude スキルをそのまま探索パスに指定できます。


## ビルド

フロントエンドをビルドしてから Go をビルドします。成果物はバイナリへ埋め込まれます。

```
cd web && npm install && npm run build && cd ..
go build ./cmd/ivis
```

`-o` は付けないでください。付けると Windows で拡張子の無いファイルができます。

**起動したままだとバイナリを上書きできない** ため、実行中の Ivis を止めてからビルドしてください。
止めずに走らせると `The process cannot access the file` で失敗し、古いバイナリが
そのまま残りつづけます。

## 起動

```
./ivis
```

既定で `http://127.0.0.1:8317` を待ち受けにします。初回起動時に `~/.ivis/config.json` と
エージェントの雛形を書き出します。設定とエージェント定義は画面から編集でき、その結果は
そのままファイルへ書き戻ります。その際、手で書いたコメントや並び順は失われます。

エージェントは Tier と呼ばれる階層を持ちます。数字が小さいほど上位で、委譲できるのは自分より
数字の大きい相手に限ります。会話の入口となる `general` は Tier 0 で固定され、削除
できません。消されていれば起動時に復元されます。

会話はそれぞれ自分の作業ディレクトリを持ち、`<作業ディレクトリ>/series/<会話 ID>/`
に置かれます。ファイル操作はその中に限られ、会話を削除してもディレクトリは残ります。

別マシンの Ollama を使う場合は設定画面か `~/.ivis/config.json` の
`ollama_base_url` を変更してください。

## ツール

定義された `tools` で許可したものだけが渡されます。

| ツール | 挙動 | 確認 |
|---|---|---|
| `list_dir` / `read_file` | 一覧と読み取り | - |
| `find_files` / `search_text` | 名前と中身で探す | - |
| `write_file` / `edit_file` | 全文置換と部分差し替え | 要 |
| `move_file` / `delete_file` | ファイルの移動 / 消去 | 要 |
| `run_command` | コマンドを実行し、終わるまで待つ | 要 |
| `start_process` / `stop_process` | 走らせたまま残す / 止める | 前者のみ要 |
| `read_process` / `write_process` | 出力を読む / 入力を送る | 後者のみ要 |
| `web_search` / `fetch_url` | Web を検索する / ページを読む | - |
| `ask_user` | 質問する | - |
| `load_skill` / `run_skill_script` | スキルを読む / 同梱スクリプトを実行 | 後者のみ要 |
| `delegate` | 下位のエージェントへ任せる | - |
| `send_message` | チームの相手へ渡す (チームのみ) | - |
| `create_ticket` / `update_ticket` | 起票 / 更新・注記 (チームのみ) | - |
| `get_ticket` / `list_tickets` | 1 件を読む / 一覧 (チームのみ) | - |
| `delete_ticket` | 1 件を注記ごと消す (チームのみ) | - |

対話を求めるもの (REPL、`input()` を持つスクリプト) と、終わらないもの
(サーバー、監視) は `start_process` で走らせたまま残し、`read_process` と
`write_process` でやり取りします。問われる内容が先に分かっているなら、
`run_command` の `stdin` に答えを渡すだけでOK。

`ask_user` は、答えによって作るものが変わり、かつ自分では決められないときだけ
使われます。それ以外は妥当な既定を選んで進み、置いた前提を答えに書き添えます。

確認を求めるツールは設定で個別に外せます。検索の取得元も設定で選んでください。既定の
`duckduckgo` は鍵が要らない代わりに先方の作りが変わると壊れるので、その場合は
`brave` か `tavily` に鍵を入れて切り替えてください。

ファイル操作とコマンド実行は、既定ではその会話の作業ディレクトリの中に限られます。
エージェント定義の `unconfined` を真にすると、この端末のどこでも読み書きでき、
そこでコマンドを実行できるようになります。委譲した先には引き継がれません。

## 生成が止まるとき

生成そのものに時間の上限は置いていません。時間で切ると、長い仕事ができなく
なるためです。上限を置くのは**何も届かない時間**のほうで、既定は 5 分
(設定の「無応答の上限」)。

これはモデルが考えている間ではなく、通路が死んでいる間に伸びます。別の端末の
Ollama を VPN 越しに使うと通路は黙って落ち、落ちたことはどちらの側にも
伝わりません。上限が無いと、そこで永久に待ち続けます。大きなモデルの読み込みが
5 分を超えるようなら、この値を延ばしてください。

死んだ接続をそのまま使い回してしまうことがあります。落ちたことは伝わらないので、
送っても応答の頭すら返りません。そこで、**使い回した接続から `head_timeout_sec`
(既定 90 秒) のあいだ応答の頭が返らなければ、接続を張り直して送り直します**。
繋ぎ直したばかりの接続には掛けません — そちらで頭が遅いのは、モデルの読み込みや
長い入力の読み取りが理由でありうるからです。

## チームセッション

複数のエージェントが 1 つの会話に居て、手番を回す形態です。左パネルの
「新しい会話」の右の ∨ から始めます。

- **メンバー** — 共通のエージェントか、チーム専用のエージェントを、この会話で
  有効にして使います。チーム専用の定義は `~/.ivis/agents/team/` に置かれ、
  **すべてのチーム会話で共有**されます。直せば有効にしている全ての会話に効き、
  消せば全ての会話から居なくなります。共通のものをコピーして、そこだけ手を
  入れることもできます。規定エージェントも含め、誰でも外せます。
- **メンション** — `@id` で宛先を指定します。宛先を書かない依頼は届きません
  (メンバーが 1 人だけなら、その人へ届きます)。何を頼めるかは Tier の上下で
  決まります — 上位へは**報告**、同位へは**依頼** (受諾か却下が返る)、
  下位へは**指示**。
- **右パネル** — 境目を掴むと幅を変えられます (焦点を置いて矢印キーでも。
  ダブルクリックで既定へ)。選んだ幅は覚えます。
- **チケット** — 右パネルに、状態ごとの列に分けた札を置きます (左から 新規 →
  終了)。AI 自身が起票し、担当と状態を進め、注記に経過を残します。列の中は
  優先度の高い順、同じなら期限の近い順。1 件ずつ消せるほか、`/clear` で会話ごと、
  巻き戻しならその地点より後に起票された分が消えます (それより前のチケットは
  中身ごと残ります)。

各メンバーが読めるのは**自分宛てのやり取りだけ**です。人数に比例してコンテキストが
太るのを避けるためで、そのぶん全体像はチケットが持ちます。だから送るメッセージには
「なぜそれをすることになったか」「やったこと」「相手へのメッセージ」が必ず入ります —
受け手が受け取るのはそれだけだからです。

Tier が上のエージェントには、上司としての進め方が渡ります — 仕事を分けて指示し、
部下に許可や確認を求めないこと。下位を持たないエージェントには、受けた仕事を
やり切る側の進め方が渡ります。

生成はブラウザの都合と切り離して走ります。更新しても閉じても止まらず、開き直せば
その続きが流れてきます。止まるのは中断したときだけです。

手番は 1 体ずつ順に回します。作業ディレクトリは会話に 1 つで、同時に書けば同じ
ファイルの結果が不定になるためです。互いに送り合って止まらなくなった場合は、
`max_turns` (既定 24) で打ち切ります。誰にも渡さずに終わった手番は、頼んだ側が
待ち続けないよう、Ivis が代わりに 1 通返します。

## コンテキスト長

1 回の生成でモデルへ渡せる量。設定の `context_tokens` (既定 16384) で決まり、
モデルが持てる値のほうが小さければそちらで頭を打ちます。エージェント定義の
`options.num_ctx` があれば、そちらが優先されます。

上限に近づくと、Ivis がこれまでのやり取りを自分でまとめます。まとめる場所は
2 つで、ターンの終わり (使用量が 90% を超えたとき) と、ツールを往復して
いる最中 (80% を超えたとき) です。往復の中で読める使用量は 1 往復ぶん古い
ので、そちらは早めに見ます。まとめても入らずに生成が打ち切られたときは、
1 度だけまとめ直してやり直します。

`/compact` で手動でも実行できます。`/compact <内容>` と書けば、何を残して
何を捨てるかの指示を差し替えられます。まとめても元の発言は消えないので、
巻き戻せばまとめる前へ戻せます。


## Discord

設定画面でボットのトークンを入れて有効にして接続します。招待したチャンネルで
メンションされたときだけ、そのメッセージへのリプライとして応答します。チャンネル
ごとに会話が 1 つでき、Web の一覧からも読むことが可能です。

呼びかけの先頭に `/` を付けると、エージェントへの依頼ではなく Ivis への指示に
なります。Discord のスラッシュコマンドとして登録しないので招待の権限を
足す必要はありません。

| コマンド | 何をするか |
|---|---|
| `@Ivis /stop` | 走っている生成を止める |
| `@Ivis /clear` | このチャンネルの履歴を消去 |
| `@Ivis /help` | 使えるコマンドを出す |

大文字小文字は問わない。知らない名前を打つと一覧が返る。

## 他の端末から

待ち受けアドレスは設定画面か `listen` で変更可能です。変更を適用するには再起動してください。

- `127.0.0.1:8317` — 実行端末のみ (既定)
- `100.64.0.1:8317` — Tailscale などの VPN のアドレス (実行端末が VPN 上で持っている実際のアドレスに置き換えてください)
- `0.0.0.0:8317` — すべての経路に開く

現時点で Ivis に認証は無く、届いた相手はファイルの読み書きとスクリプトの実行を行えてしまうため、変更は慎重にお願いします。
ループバック以外へ束ねるなら、到達できる範囲そのものを絞ってください。

## 開発

フロントエンドを触る間は Vite の dev server を使います。`/api` は Go 側へ中継されます。

```
./ivis            # 別の端末で
cd web && npm run dev
```

テストは `go test ./...` と、フロントエンド側の `cd web && npm test`。
